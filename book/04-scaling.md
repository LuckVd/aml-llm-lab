## 1. 三条经验定律，一个函数

训练结束的 val loss 大致只由两个量决定：参数量 N、训练 token 数 D：

```
L(N, D) = E + A/N^α + B/D^β
```

人话翻译：

- **E（地板）**：语料本身的不可约熵——神仙模型也不可能低于它
- **A/N^α**：模型不够大导致的损失（容量瓶颈），幂律衰减
- **B/D^β**：数据不够多导致的损失（见过的世面不够）
- α、β ≈ 0.3 上下：**幂律**意味着花 10 倍代价只买走一大半损失，永远到不了零——这也是为什么"多买算力"一直是安全的投资

Kaplan et al. 2020 先发现幂律；Hoffmann et al. 2022（Chinchilla）修正了结论：
同样的算力，**小模型喂更多数据**比大模型饿着训更好。

## 2. 怎么拟合一个非线性两三项式？

L 不是 N、D 的线性函数，普通最小二乘直接解不出来。业界标准做法（也是 CS336 的做法）：
**把参数搬进 torch，用梯度下降拟合**：

```
可训练量: log A, α, log B, β（E 当常数给定）
损失:     MSE(log L̂(N_i, D_i), log L_i)
```

log 空间放 A、B 是为了保证正数；**损失也要在对数域算**——原始 MSE 会被高 loss 点
（小模型的 loss ~10）主导，低 loss 点（大模型 ~2.5）几乎被忽略，参数会系统性跑偏。
几千步 Adam 就收敛，CPU 上几秒。
拟合完的曲线可以回答训练时没人知道答案的问题——"要是当时多喂 10 倍数据会怎样"。

## 3. 计算最优：给定预算 C，N 和 D 怎么分？

预算约束 `C = 6·N·D`（训练 FLOPs 的著名近似：前向 2ND，反向 ≈ 2 倍前向）。
代入 L(N, D=C/6N) 后只剩一个自由度 N，网格搜索 log 空间取最小即可：

```
for N in 对数网格:
    D = C / (6N)
    L = E + A/N^α + B/D^β
取 argmin
```

Chinchilla 的著名答案：在 1e18–1e20 FLOPs 区间，**D*/N* ≈ 20**——每个参数配约 20 个训练 token。
（Kaplan 时代的错误答案是 ~1：模型大、数据少，GPT-3 就是这么训的。）
注意 D*/N* 不是常数：预算越大，"每个参数配的 token"越多（1e17 档约 20，1e21 档约 50）。

## 4. 系统一侧：MFU，即"你的 GPU 有几分之几在干活"

```
MFU = 实际 FLOPs / 峰值 FLOPs = (6 · N · tokens) / (peak · 时间)
```

`systems_benchmark.csv` 里 20M 模型在 A100 上 ~1.4M tokens/s → 对应 MFU ~0.6；
而你 lab03 的 CPU 大概 3 万 tokens/s。差距 50 倍——这就是"过夜"与"点杯咖啡"的区别。
小 batch 的 MFU 显著更低：算子喂不满硬件，这也是 batch size 存在的根本理由。
