## 1. 为什么 SFT/DPO 之后还需要 RL？

SFT 和 DPO 都在**模仿**：模仿示范答案、模仿偏好判断。它们的天花板是数据本身。
RL 打开的局面完全不同：**只看结果打分，怎么达成让模型自己想**。
AlphaGo 的自我对弈、o1/R1 的思维链进化，走的都是这条路。

RLVR（RL with Verifiable Rewards）：答案对不对可以**机器判定**的任务（数学、代码、格式），
reward = 判定结果，1 或 0——不需要人类标注，也就没有标注偏差和规模上限。

## 2. PPO 的三座大山，GRPO 砍掉了哪座

经典 RLHF-PPO 要维护：策略 π、价值网络 V（当 baseline）、奖励模型 R、冻结参考 π_ref——
四张计算图伺候一个 loss，显存和工程都痛苦。

GRPO（DeepSeek 数学系列/­R1 用的方法）的洞察：**同一道题采样 G 份答案，
用组内平均当 baseline**，价值网络就可以整个扔掉：

```
A_i = (r_i − mean(r_1..r_G)) / (std + ε)      # 每个答案的"组相对优势"
loss = − E[ min(ρ_t·A, clip(ρ_t)·A) ] + β·KL(π ‖ π_ref)
ρ_t = π_new(a_t|s) / π_old(a_t|s)             # 重要性采样比（PPO 同款）
```

直觉：比同组平均好的答案，把它的生成概率推高；比平均差的，压低。
**全对或全错的组 A≡0，没有信号**——GRPO 的有效区在"成功率中间地带"，
这也是它天然适合课程学习（从简单题 bootstrap）的原因。

## 3. 本 lab 的最小实现

- 任务：一位数加法（`3+4=`，0..4 + 0..4 共 25 题，答案 1 位）——level 2（两位数）作为思考题探针
- 底座：lab02 架构的小模型（字符级词表），先在"数字汤"上预训练：格式总是正确，
  **答案三成是对的**。这是对 R1-Zero 的诚实微缩——base 必须带一点"毛坯先验"（火花），
  RL 的工作是放大它，而不是无中生有（把正确率调成 0 试试，GRPO 会卡死在随机水平）
- rollout：对每道题采样 G 个答案，记下每个 token 的 logπ
- 一个 batch 里**每道题单独成组**（batch 维 = G 份同一 prompt），天然等长、不需要 padding
- µ=1（每个 rollout 批只更新一次）：ρ≡1，clip 不激活——此时 GRPO 退化为
  **带组基线的 REINFORCE**；代码仍实现完整 clip 逻辑，µ>1 时自动生效
- KL 惩罚用最简单的 k1 估计（E[logπ − logπ_ref]），β=0.05——经验上这是本玩具的"稳定锚"

## 4. 你会亲眼见到的 RL 现象

1. **放大，不是发明**：底座采样命中率 ~15-30%，GRPO 把它推到 60-70%——
   RL 放大既有能力；没有火花的 base（正确率 0 的数字汤）RL 救不了
2. **熵塌缩**：β 调到 0 或 lr 调到 3e-3，模型很快把概率质量砸死在个别错误答案上——
   组内全错 → A≡0 → 零梯度 → 永久卡死。KL 锚就是防这个的
3. **奖励黑客的原型**：若 reward 只查首位数字，模型会学会"首位对、次位乱"——
   判定器写错，模型精准地利用它（本 lab 的判定器是全串精确匹配，不给黑客留门）
4. **稀疏奖励的天花板**：level 2（答案 3 位）随机命中率 1/1000，一组 8 个几乎必全错——
   没有信号，课程学习（先易后难）是 RLVR 的生命线，R1 团队也是这么熬的
