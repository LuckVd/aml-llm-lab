## 1. Agent = 一个 while 循环

剥掉所有包装，agent 就是：

```
历史 = [问题]
重复最多 N 轮：
    输出 = 模型(提示词 + 历史)
    若 输出是最终回答: 结束
    若 输出是工具调用: 历史.append(工具执行结果)   # 观察 observation
    否则: 历史.append("格式错误，请输出 JSON")      # 兜底
```

真正的工程量全在**协议**上：怎么让模型稳定输出可解析的动作（JSON）、怎么解析
不守规矩的输出、怎么防死循环。这跟 lab05 的道理一样：能力一半在模型，
一半在你设计的**格式协议**。

## 2. 工具：把"嘴"接到"手"上

LLM 的弱项（精确计算、计数、查事实）恰恰是解释器的强项。工具函数三件套：

- **签名要窄**：`calc(expr)` 只接受算术表达式——不接受任意 Python（`__import__` 就完蛋了）。
  用 `ast` 解析表达式树、只放行 `+ - * / // % **` 和数字节点，这是白名单思维
- **报错不是异常**：工具返回 `"Error: division by zero"` 字符串进历史，agent 能自我纠正；
  抛异常出去循环就死了
- **描述写进提示词**：模型只会调它"知道"的工具，工具的 docstring 就是模型的 API 文档

## 3. Self-judge：让模型给自己的答案打分

生成之后加一道便宜的自检：

```
裁判提示词 = 问题 + 完整轨迹（含工具观察）+ 答案 + "这个答案对吗？先推理，最后回答 YES 或 NO"
```

用途立竿见影：**best-of-n**（采样 n 个答案，自评 + 多数投票挑最好的）、**过滤幻觉**、
**给 RL 当弱奖励**（lab07 的 verifiable reward 是它的严格版——规则能验证的绝不请裁判）。

要警惕的是裁判的系统性偏差：偏爱长答案、偏爱自信语气、位置偏差（多选时偏向第一个）。
真实系统里裁判和人审要定期对齐（裁判也是模型，也会被 reward hack）。

## 4. 本 lab 的架构

```
agent.py
├── calc / count_words        工具（白名单安全）
├── build_prompt              协议：系统提示 + 工具文档 + 历史
├── extract_json / parse_action   鲁棒解析（fenced JSON / 散文里的 JSON / 坏格式兜底）
├── run_agent(model_call, ...)    上述 while 循环；model_call: str -> str（可插拔！）
├── rule_judge                    规则裁判（精确匹配，归一化后比较）
├── self_judge(model_call, ...)   模型裁判（YES/NO 解析）
└── main()                        接 Qwen 0.5B 真跑
```

`model_call` 是个普通函数——测试里用"剧本模型"（按剧本吐 JSON 的假模型）替身，
离线把协议逻辑全部测干净；真模型只是换了函数指针。这就是依赖倒置的最小实践。
